## P1 · The decision record (26 Oct 2026)
One decision = one tree row `<Branch>.<Stage>.<Step>`. Columns: identity (question, stage, branch, depends-on) · options with fact cards (cost P50–P90, build time, owner taps, automation %, safety tier, paid potential, benefits, negatives, confidence tier × age → staleness, source span + hash + date) · ★ (option, one-line why, confidence, regret rank) · decision (chosen, asserted_by ∈ {owner, ★ taken, ★ batched}, at, superseded_by, invalidation condition per declined option) · acceptance (executable line, hash, registered-at, red-first proof, tier visible/sealed, pass^k, mutation score, flakes) · build (parts + versions, kitVersion, estimate → actual) · risk (blast-radius tier auto / notify-with-cancel / block, undo?, constitution lines) · feasibility (untried / tried-and-failed with expiry / blocked-by-policy, reason type, dependency edge) · status (proposed → decided → built → verified → live → superseded).
Every change is an append-only event with content hash + parent hash.
Shown as one folded card: question · ★ with one-line why · confidence dot · facts age · [Take ★] [Show others] [Ask me later]. Decided → one line with a status dot (○ not run · green pass k/k · red fail · yellow stale fact or not re-run since model change).
Clicks: Take ★ one tap; batch only within one tier with consequence list, never block tier; auto tier defaults to ★ with undo and digest note if untapped; block tier waits without timeout; hard decisions asked early (first 10 %), 2–3 options, with the condition that would flip ★. Measured: tap latency, override rate per ★; < 2 % override → notify-only.
Acceptance line example (C.4.1 Where does it run?): fires Monday 07:00 Europe/Zurich → by 07:10 a new ranking with ≥ 3 ideas and one run record naming the routine, none on other days; red-first; pass^3; sealed twin from the same spec (other offset; empty Monday → "nothing new", no empty ranking); mutation audit on window and count.
Later: half-life passed → yellow, re-fetch, re-hash, re-decision proposal on change; invalidation condition true → declined option re-surfaces once (digest); new primitive → retest rows on its dependency edge; kit version bump → list tools, re-render, re-run acceptance before update; estimate → actual feeds calibration (nearest three builds).
Open: auto-take after long wait in block tier (proposal: never); re-surface declined automatically or in digest (proposal: digest).

## P3 · Autonomy tiers and the measured GO (26 Oct 2026)
Tiers by blast radius and reversibility: auto (reversible, internal, no money/outward; acts, undo live, digest line) · notify-with-cancel (reversible but visible/costly/changes a default; short window, then acts, undo live) · block (irreversible or outward: money, messages, deletion, publishing, credentials, leaving the sandbox, customers' tools, changing constitution/scorer/gate; waits, no timeout, no batching). Tie-breaker: beyond what was asked? unknown infrastructure? driven by outside content? → one tier up.
PT actions: auto = research, options/★, sandbox build, tests/hunts/drills, mocks, staging re-render, digest, archive, fix-until-green within caps; notify = default promotion, untapped ★, build issue, retire part, ring-2 re-render; block = publish, payment, outward send, delete, credential/connector, first world-acting tool, ring-3 re-render, constitution/scorer/gate change.
Tools: tiers baked in from decision rows; outward tools get an in-tool block step, spend cap, own scoped credential separate from PT and from backups.
Undo: every auto/notify action is a checkpoint (node, tool version, archive event), one-tap restore, 30 days.
Questions: goals in the first ~10 %, inputs before midpoint, none after; 2–3 options with the flip condition; hard only on four triggers; owner sentences become visible policy rows.
Measured GO: latency and rejection per GO type (→ 0 means unread → shrink batch, unfold consequences); should-reject canaries ~1/20 (drill, logged); random post-approval audits 1/10 fresh-context; deputy/dead-man: unreachable owner → halt at notify, never auto-proceed; batching within tier only, one block item per card.
Breakers (pre-authorised): step cap, token/CHF cap per run and day, action-velocity, privilege-escalation attempt, three classifier blocks → stop, keep state, digest line.
Adjustments to PLAN-1.8 decisions (proposals): laptop irreversible steps stay block; drill findings open a block card; behaviour-changing fixes are notify.
1.8: tier per action class, checkpoint per node. 1.9: measured GO, canaries, audits, breakers.

## P5 · Honesty as decay (26 Oct 2026)
Fact record: value, URL, quoted span, span hash, fetched-at, class, tier (verified / found / stale / unknown), superseded_by. Half-lives (initial, recalibrated from observed change rate): prices/limits ~20 d · platform features ~45 d · versions ~30 d · policies/legal ~180 d · vendor status ~60 d · stable none. Staleness = 1 − 0.5^(age/half-life). Error budget per surface (cost card ≤ 10 %, pricing prompts ≤ 5 %, policy ≤ 20 %); above budget the fact is not used — prompt builder filters on valid_until, shows "not re-checked, likely changed". Re-check by budget, cheapest/highest-use first; outcomes: hash same → age 0; hash changed value same → "changed but answer unchanged", no inbox; value changed → superseded_by, rows using it go yellow with diff, re-decide only if ★ flips. Yellow means exactly: a fact behind an option is past budget. Contradictions: one record per fact; disagreement → both found, re-fetch, show range. Health row: right abstentions, confident-stale count (−2), measured change rate vs half-life → half-life auto-adjusts. Judges: Unknown option, span before claim. Supersedes the "90 days" decision when the owner confirms. 1.8: record + half-life table; 1.9: budget re-check, abstention scoring, recalibration.
