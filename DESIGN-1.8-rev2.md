## 2 · P1 rev 2 — the decision record as a projection
Rows are a **projection** over the project document (pick cards/log, kit decisions, p.decisions, p.arch, p.tool.versions) plus the new events collection; no rewrite of Undo or `queueOf`. Row fields in 1.8: id `<Branch>.<Stage>.<Step>`, question, options with fact cards, ★ + why + confidence, decision {chosen, asserted_by ∈ owner / ★-taken / ★-batched, at, superseded_by}, acceptance {line, hash, registered_at, red_first_at, tier, last_result}, tier (auto / notify / block), feasibility {state, reason, expires, edge}, status. Deferred to 1.9: parts traceability per row, estimate → actual, mutation score, repair lift.
Acceptance shape: three classes per decision where it applies — *exists* (the thing is there), *resolves* (the wish is met), *unchanged* (what must not change). Spec-Kit-style **analyze pass** before build: rows without acceptance, options without facts, acceptance lines no part implements, contradictions between rows → listed, build waits.
Decline conditions: owner-written or picked from PT's suggestions; rows decided by ★ have none (nothing was declined by the owner). A changed fact → PT *proposes* re-decision (notify-with-cancel), never auto-takes.
Undo: restore points (existing, never deleted by PT); each auto/notify action writes one; "undo" = restore + the list of what it cannot undo (sent messages, versions already seen, events already digested).

## 3 · P2 rev 2 — "update once for all" without a renderer
Facts: kits emit prompt blocks; a session builds the tool in `firnlab/tools/<slug>/`; re-building is an LLM run, non-deterministic; PT can republish only the session login's own artifacts.

## 16 · The flow step by step — deep pass with research (31 Oct 2026)
Verdicts: steps 0–1 ~75 % · 2 ~70 % · 3 ~55 % (→ 85 % with changes) · 4 ~70 % · 5 ~80 % · 6–7 ~80 % (→ 95 %) · 8 ~70 %. Adopted changes (owner may object):
Steps 0–1: inbox home confirmed (chat burns out ~30 s; blank first screens lose ~70 %); clarification policy — slot confidence, at most one targeted question when a direction-flipping or irreversible slot is uncertain (frontier models ask on 12–18 % of vague tasks); editable paraphrase before chips; Swiss-German dialect dictation ~26–29 % WER → show Standard-German transcript for review, "works, check the text"; zh IME composition-safe; "and"-chains → split into candidate tools (untested); attachment chips; own-data starters later; measure prompt abandonment and resumption rate.
Step 2: chips are hypotheses (slot-confidence AUROC ≈ 0.75 best, ~0.52 for GPT-4-class) → two chip kinds: "from your sentence" (span underlined) and "assumed" (what wasn't checked + cheapest way to check); no numeric confidence; cut strip with × per cut; "not sure" a real value.
