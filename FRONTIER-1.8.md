# FRONTIER-1.8 — the ten levers against the frontier (researched 25–26 Oct 2026)

Five research runs, each on two levers: frontier (who does it best, how) · rules that hold · anti-patterns · what PT's design misses, ranked.
Sources are primary where found (URL + date); SECONDARY and ESTIMATE marked. This file is the research base for PLAN-1.8; the owner
decides what enters 1.8 in the chat. Terms: "gate" = a step that cannot be skipped; "★" = PT's recommended default.

## 1 · Intent as decisions
**Frontier.** Kiro specs (requirements.md with EARS criteria "WHEN … THE SYSTEM SHALL …", design.md, tasks.md, each task `_Requirements: 1.1_`); GitHub Spec Kit (a `constitution.md` of non-negotiables, /specify what-why without stack, /plan against the constitution, 15 Sep 2025); Anthropic's Claude Code practice (interview → SPEC.md → execute in a fresh session; spec names files, out-of-scope, ends with an end-to-end verification; plan mode skipped when the diff fits one sentence); Codex plan mode + "define done in AGENTS.md"; Devin's green/yellow/red confidence (green tasks 2× more likely merged, 15 May 2025); research: ClarEval — pass 8.9 % ambiguous vs 89.0 % clarified (19 Jun 2026); "Ask or Assume?" — a separate intent agent that flags gaps lifted 61.2 → 69.4 % (arXiv 2603.26233, Sep 2026); agent-written ADRs with provenance (28 Apr 2026).
**Rules.** Separate what/why from how; every task traces to a numbered decision; every spec ends with a runnable verification; ask only on missing success criteria, several readings, unstated environment, ambiguous term — otherwise look and proceed; the "should I ask?" judgement is a separate role; show confidence, not just the plan; record who decided and supersession; execute from a fresh context with the record, not the chat.
**Anti-patterns.** Vibe architecting (decisions made by defaults, no record); fabricated rationale; planning everything; bloated rule files; guessing on ambiguity; AI-written change descriptions hiding context.
**We missed (ranked).** 1 No traceability from built parts to decision numbers · 2 No acceptance line per decision (EARS) — verification has nothing precise to grade · 3 Ask policy has no trigger list and no separate checker · 4 No confidence signal to the founder per ★ · 5 No constitution above the tree (cross-tool invariants) · 6 No provenance per decision (who/when/superseded) · 7 Fresh-context handoff not stated · 8 No "edit the record directly" affordance.

## 2 · Reach
**Frontier.** Claude Code Routines (schedule / GitHub event / tokened `/fire` API; cloud VM; connectors scoped; Apr 2026); artifacts calling each viewer's MCP connectors (Jul 2026); Mods (panes in Claude Code, Oct 2026); dynamic workflows of subagents; Managed Agents public beta (8 Apr 2026; USD 0.08/session-hour + tokens; memory stores; subagents one level); Claude Tag in Slack (shared identity, ambient mode, 23 Jun 2026); Claude in Chrome GA on paid plans (26 Aug 2026); OpenAI retreated from a standalone browser to an extension (Aug 2026); Cloudflare Agents SDK on Durable Objects (hibernation ≈ free idle); MCP Apps (tools with UI, 26 Jan 2026) and A2A 1.0 (Apr 2026); Apple Foundation Models with skills (WWDC 2026) and Android ML Kit Prompt API; Home Assistant's built-in MCP server (~95 tools); WhatsApp bans general chatbots from 15 Jan 2026; realtime voice ≈ USD 0.06/min in, 0.24 out (SECONDARY).
**Rules.** Cheapest surface that satisfies the trigger (routine < managed agent < own server); every trigger payload untrusted; branch protection on main before any cloud agent pushes; green ≠ done; phone = PWA first (EU web distribution gated by eligibility; Swiss users outside the DMA); messaging bots business-ancillary; browser agents block finance sites and confirm consequential actions.
**Anti-patterns.** All connectors on a scheduled agent by default; relying on routine memory (fresh VM each run); expecting home-dir config in the cloud; a general WhatsApp bot; a standalone browser; long Managed Agent sessions without heartbeat (checkpoints expire 30 days).
**We missed (ranked).** 1 Routines as the main implementation of C (schedule + GitHub-event + API triggers) · 2 "Live page" (B calling viewers' connectors) and the pair B+L · 3 Slack / Claude Tag as a surface for D and H — a cheaper "company" · 4 MCP server / MCP App as a sellable product (E, I) · 5 Mods for J · 6 Policy gates in the tree (WhatsApp rule, EU/CTC, notarization) — ask "where will people use it?" early · 7 Managed Agents vs Agent SDK chooser for D · 8 On-device phone models and Home Assistant MCP for F/J · 9 Voice absent.

## 3 · Verification
**Frontier.** Anthropic "Demystifying evals for agents" (9 Jan 2026): code/model/human graders, **pass^k** (75 % per trial = 42 % over three), 20–50 tasks from real failures, a reference solution per task, should-do and should-not-do cases, clean environment per trial, outcomes not tool paths, judges with "Unknown", one judge per rubric dimension, "read the transcripts"; Claude Code's `/goal` evaluator each turn, Stop hooks that block completion until a script passes, a verification subagent in a fresh context, evidence over assertion; metamorphic testing at scale (LLMORPH, Mar 2026); judge position bias measured (swap order, flips = ties); production traces → golden set → CI (Braintrust, 26 Sep 2026); OWASP Agentic Top 10 (ASI01–10, 9 Dec 2025).
**Rules.** Binary verdicts; read 30+ traces before automating; validate every judge against human labels; report pass^k; reference solution per golden; negative goldens; doer ≠ grader; deterministic gates over advisory text; bound the reviewer to correctness gaps; evidence, not assertion; evals plus monitoring.
**Anti-patterns.** Grading tool-call sequences; shared state across trials; 100 % evals read as improvement; vague rubrics; judges without Unknown; shipping what can't be verified; single-window alerts; agent-written tests reviewed by the same agent.
**We missed (ranked).** 1 No pass^k rule (all k must pass for outward tools; show per-trial rate) · 2 No reference solution per golden · 3 No negative goldens ("should refuse / not act") · 4 Judge calibration named, not specified · 5 No deterministic stop gate (proof rules as scripts in a hook where possible) · 6 No production → golden → gate loop · 7 Reviewer scope unbounded · 8 Drill not mapped to ASI01–10 · 9 Clean environment per trial unstated · 10 No metamorphic checks · 11 Transcript reading not a rule.
**Cross-link.** One missing object ties levers 1 and 3: a decision record whose acceptance criterion is executable and which the build cannot mark done until that test passes.

## 4 · Compounding memory
**Frontier.** Claude Code auto-memory (v2.1.59, Feb 2026): typed notes (user/feedback/project/reference), an index capped at 200 lines/25 KB, topic files on demand, skip what the code or CLAUDE.md already says; ACE (ICLR 2026): generator/reflector/curator, itemised bullets with helpful/harmful counters, delta updates merged by code — full rewrites cause "context collapse" (18k → 122 tokens, below no-memory baseline); `/doctor prompt-audit`; `claude plugin eval` with-vs-without Δ gating instruction changes (12 Sep 2026); path-scoped rules; Cursor removed auto-memories (Nov 2025) — unsupervised memory is hard to trust; MINJA memory-poisoning (62 % success on empty memory, arXiv 2503.03704 v5, Feb 2026).
**Rules.** Instructions I wrote ≠ learnings the agent wrote; store only what can't be derived; cap the always-loaded layer; delta-update with evidence counters; memory is context, not enforcement (hard rules in hooks); audit contradictions; human-readable and deletable; eval before a lesson changes behaviour.
**Anti-patterns.** Full rewrites; brevity bias; memory from untrusted inputs without a trust gate; unbounded always-on memory; invisible/undeletable memory; prompt-only safety; secrets or derived facts in memory; contradictory rules accumulating.
**We missed (ranked).** 1 No override → default promotion loop (typed feedback entries with counters; promote after N confirmations across ≥ 3 tools and a passing eval Δ; retire after M harmful) · 2 No trust gate on what enters memory (provenance tag user-stated / observed-in-test / web-radar; only the first two can become defaults; radar facts are dated reference) · 3 No cap/index discipline · 4 No eval before a default changes (10–20 golden wishes) · 5 Learnings mixed with rules · 6 No contradiction audit · 7 Ledger lacks decay.

## 5 · A library of proven parts
**Frontier.** shadcn GitHub registries (any repo with registry.json; items = components, hooks, tokens, workflows, agent instructions; Jun 2026); Agent Skills spec (SKILL.md with name, description ≤ 1024, license, compatibility, metadata, allowed-tools; validator; adopted by Claude and Copilot); Claude Code plugins (versioned, licensed, dependencies, `sensitive` config, data dir kept across updates, evals, strict validation, reserved names); SLSA after "Mini Shai-Hulud" (11 May 2026: 170+ packages compromised with valid attestations — require the expected builder, digest-pin actions); licence gating of agent output (Black Duck 2026: conflicts in 68 % of codebases); Spotify golden paths (templates with owners and an architecture group); Renovate release-age delays and grouped PRs.
**Rules.** Every part: name, when-to-use description, licence, version, compatibility, tests, owner, verified_on; pin then update deliberately with soak time; code ≠ state; validate strictly in CI; provenance necessary not sufficient; scan licences at write and release; curate, don't crowdsource; progressive disclosure for parts.
**Anti-patterns.** Signature = trust; auto-merging majors; state inside the versioned part; unlicensed snippets; vague descriptions (never picked); instructions in the wrong file; an open shelf without an owner; secrets in part config.
**We missed (ranked).** 1 Parts need a manifest and a registry (registry.json + SKILL.md-style frontmatter) so PT discovers them at plan time · 2 "Update once for all" needs pinning + soak + rollback per tool · 3 Each part needs its own with-vs-without eval · 4 Provenance and licence gates (SPDX, ScanCode, SBOM per tool, digest-pinned actions, builder identity) · 5 State/config separation per part · 6 Stable kit rules → Skills · 7 One owner and an intake note per part.
**Cross-link.** A lesson confirmed ≥ N times graduates from memory (lever 4) to a versioned part with tests (lever 5) — that is what makes tool #100 smarter and cheaper.

## 6 · Economy
**Frontier.** Prompt caching: 512-token minimum on 5.5-generation models, reads 0.1× (0.05× Opus/Sonnet 5.5, 0.025× Fable 5.1), 5-min write 1.25×, 1-h write 2×, hits refresh free, automatic breakpoint, prefix order tools → system → messages, changing tools invalidates everything; Batch 50 % and stacks with cache; effort/adaptive reasoning as a cost dial (Opus 5: ~17 % fewer output tokens); structured outputs (json_schema, strict tools) remove retry loops; routing/cascading mature (RouteLLM ≥ 85 % cost cut at 95 % quality) but needs a scorer; server-side context editing; cost observability (Langfuse: per-trace cost, outliers, rolling alerts, gateway caps).
**Rules.** Stable prefix first; test `cache_read_input_tokens` > 0; 5-min TTL by default; batch anything that can wait an hour; smallest model that passes a measured eval; code for deterministic steps; measure realised savings against an invoice; output tokens are the expensive side — short outputs and low effort are the biggest knob.
**Anti-patterns.** Caching below the minimum; rotating tool sets per call; tokenizer-based estimates; double-counting cached tokens; routing by task name without a difficulty signal; "smaller model" via longer prompts; unbounded loops with retries; no per-run attribution.
**We missed (ranked).** 1 No measurement — log every run's usage object, cached share, output tokens, step count; taps and wall-clock to first version; alert on daily total · 2 Caching rule underspecified (floor check, prefix order, one breakpoint, TTL policy, never rotate tools) · 3 Effort/thinking budget missing from the seven rules · 4 Structured outputs not in the brief · 5 Batch needs a trigger rule · 6 Cascade needs a scorer · 7 Context compaction / tool-result truncation absent · 8 Per-run budget cap (steps and money).

## 7 · The right autonomy
**Frontier.** Claude Code `auto` mode: a separate classifier reviews each action (blocks escalation beyond the request, unrecognised infrastructure, actions driven by hostile content; 3 blocks in a row pause it; explicit asks never auto-approved); Cursor Auto-review (allowlist → sandbox → classifier; plain-English allow/block instructions as settings); Operator takeover mode for credentials/payment and confirmation before external side effects; CSA Agentic Autonomy Levels v2 (18 Mar 2026): L1 per-action approval + undo, L2 approve a plan then auto with checkpoint rollback, L3 act within enforced boundaries with escalation and kill switch; clarification science: goal questions at ~10 % of the trajectory lift pass@3 0.40 → 0.78, late questions are worse than none (arXiv 2605.07937, May 2026); people ask when expected regret exceeds a threshold; "which of 8?" is the least welcome question.
**Rules.** Gate by blast radius and reversibility, not complexity — auto / notify-with-cancel / block (money, outward, prod, delete, publish); keep the auto tier large (~10–20 real decisions per session is the attention budget, ESTIMATE); review the policy, not each action; undo over confirm for reversible actions; show consequences not commands; narrow saved approvals; trust scoped by action class; ask about goals first, inputs before halfway, never a new question after the midpoint; instrument approval latency and rejection rate (< 800 ms ≈ not read; ~0 rejections = decorative gate); the sandbox is the real approval.
**Anti-patterns.** Prompt on everything; one-tap OK for destructive actions (Replit prod-DB, PocketOS, `rm -rf ~` incidents); YOLO mode after fatigue; blanket trust escalation; raw commands in confirmations; denylists as force fields; asking late; asking "which of 8".
**We missed (ranked).** 1 No undo/rollback layer (checkpoint per node, "revert this node") — with it many ★ nodes need no tap · 2 Tiering by node instead of blast radius · 3 "Take all ★ on this level" batches mixed-risk items — batch only within a tier, with a consequence list · 4 No timing policy for questions · 5 No loop instrumentation (tap latency, override rate per ★; drop the tap where overrides < 2 %) · 6 Decide-by-sentence should become persistent policy (reviewable settings) · 7 Sandbox-as-approval unused for laptop tasks (worktree/container, allowlisted hosts) · 8 Hard nodes need a classifier (the three Claude Code questions) · 9 Pruning order by expected regret.

## 8 · Honesty as a mechanism
**Frontier.** OpenAI "Why language models hallucinate" (5 Sep 2025): abstention scored, confident errors penalised; Anthropic Citations API (23 Jun 2025): sentence-level spans attached to claims; CiteAudit (May 2026): verification is a tool chain (0.949 vs 0.559 for one LLM); risk-constrained freshness (Jul 2026): staleness as exponential decay with per-class half-lives (≈ 22 d / 16 d / 15 h / 3 h / 30 s), re-use only under an error budget → 0.1 % stale vs 14.9 % with fixed TTLs; only 34 % of page changes change the answer; HTTP Last-Modified honoured by 11 % of sites — hash content; freshness metadata (valid_from/valid_until/superseded_by; expire before retrieval; content-debt tickets; hallucination 10 → 66 % on outdated context); LLM judges track consequences (85.6 % mislabel in one setting; Anthropic 13 Jul 2026).
**Rules.** Score abstention (+1 right, 0 unknown, −2 confident wrong); cite spans with hash, URL, date; verify artifacts, not status; expire before retrieve; separate found from verified; show the date on every surface.
**Anti-patterns.** Fixed TTL per fact type; trusting HTTP headers; "ask Claude if it changed"; URL-only citations; "no change detected" read as "true"; a confidence tier assigned once and never decayed.
**We missed (ranked).** 1 Confidence should decay (tier × age → staleness probability with per-class half-lives; AI prices ~15–30 d half-life, not a 90-d TTL; refuse past the error budget) · 2 Store the quoted span and a content hash · 3 Score PT's own abstentions on the health page · 4 Contradiction detection across cards (superseded_by) · 5 Judge debiasing with a machine-readable abstain · 6 valid_until as a hard filter in the prompt builder · 7 "Changed but answer unchanged" as a state · 8 Low-confidence retrieval → inbox item.

## 9 · Composition
**Frontier.** Anthropic orchestrator-workers (lead Opus + Sonnet subagents +90 %; agents ≈ 4× chat tokens, multi-agent ≈ 15×; token spend explains 80 % of outcome variance; 1 / 2–4 / 10+ subagent ladder; plan saved to memory before fan-out); Claude Code agent teams (shared task list with dependencies, file-locked claiming, TaskCompleted hooks as gates; one team per session, no nesting); durable execution as table stakes (Temporal + Agents SDK sandboxes Apr 2026, Cloudflare Workflows, DBOS, Inngest; one step = one expensive call; test by killing a run mid-flight); A2A 1.0 agent cards, MCP Apps; MAST (NeurIPS 2025): 14 failure modes in specification, inter-agent misalignment, verification — mostly organisational.
**Rules.** Scale agents to breadth, not ambition; compose only when parallel and context-independent; subagents before teams; every expensive call a durable step with state outside the process; inter-agent messages untrusted — a relayed approval is not consent; plan written to a durable record before fan-out; verification is a role; fix tool descriptions before prompts.
**Anti-patterns.** Parallel agents editing the same file; the lead doing the work or stopping early; status lag as truth; synchronous subagents; renaming hash-keyed steps; orchestration outside step boundaries; unbounded nesting; no budget hierarchy.
**We missed (ranked).** 1 No typed contracts between tools (one JSON schema per record type, validated on write; labels for state; dependency links) · 2 No durable execution (idempotent runs keyed on the issue; a Routine or Workflow per issue; Managed Agents session per task) · 3 No budget hierarchy (per tool, per issue, effort ladder before fan-out) · 4 Verifier role with power to reopen · 5 Untrusted-message rule (founder decisions signed, never relayed) · 6 Shared memory undefined · 7 Lighter compositions exist (subagents in one session, cross-session messaging, Claude Tag) — route to the lightest · 8 Pairs lack an interface contract · 9 No "when not to compose" check.

## 10 · Self-growth
**Frontier.** Voyager (skill enters the library only after it executes); AlphaEvolve (automated evaluators are the whole game, May 2025); Darwin Gödel Machine (archive with non-greedy parent selection; 50 % vs 39.7 % greedy; **objective hacking observed**: the agent removed the logging its hallucination detector relied on — caught only because the detector was hidden from it; Mar 2026); Sakana AI Scientist v2 (passed peer review, 57 % of papers had wrong numbers — passing a gate ≠ being right); Anthropic agentic misalignment (covert sabotage in 11/20 runs for one model; verify artifacts not summaries; 13 Jul 2026); METR on evaluation awareness (12 Mar 2026); change detection commoditised (content-diff monitors, GitHub releases.atom).
**Rules.** The evaluator lives where the proposer cannot edit or see it; prove by execution with a pre-registered acceptance test; keep an archive, not a single best; independent re-measurement of claimed gains; agents propose, humans dispose; artifact diff at merge.
**Anti-patterns.** Scorer and proposer in one codebase; "passed review" as proof; greedy keep-the-best; self-reported success as the signal; the classifier scoring its own labels; open-ended web scanning instead of a fixed source list; retiring by calendar alone.
**We missed (ranked).** 1 Separation of powers (scorer, gate tests and health metrics in a repo the growth agent cannot write; log every touch) · 2 Pre-registered acceptance test in every proposal · 3 Independent second measurement (weekly spot-check of 3 "improved" claims) · 4 Archive instead of retire, with lineage and revival · 5 Judge debiasing for the classifier · 6 Artifact diff at merge · 7 Goal-drift guard: security and owner-time as constraints that must not worsen, not scored goals · 8 "Changed but irrelevant" state to stop inbox floods · 9 Some gate checks on unannounced inputs · 10 Retire by usage and dependency, not usage alone.

## 11 · Frontier awareness (added 26 Oct 2026, owner's question)
**Today.** Sunday knowledge check of known facts; vault mirror; 90-day fact age; growth loop (designed, not built). Nothing looks for the unnamed; no dated, proven list of what PT can do. ≈ 2/10.
**Ceiling (≈ 9/10).** Four layers: (1) capability ledger — every primitive (model/platform feature, vault tool, technique) with enables / since / proof run / cost / licence / tree position; the planner matches wishes against the ledger; (2) freshness by decay + content hash per entry (lever 8); (3) delta pass — each new entry is matched against the tree's **impossible list** (every step marked impossible/expensive/needs-human with its reason); reason ↔ primitive hits become growth proposals with pre-registered tests (lever 10); (4) horizon list — release calendars (Anthropic weekly cadence, I/O, WWDC, DevDay, MCP/A2A/OWASP/SLSA cycles, NeurIPS/ICLR/ICML) and source types ordered by lead time: arXiv (6–18 mo) → authors' repos (3–9 mo) → official changelogs/docs (day 0) → practitioner write-ups (weeks 1–4); machine-readable signals: artifact capability roster, model cards, price-list rows, new MCP server types.
**Rules.** found → proven (executes in a PT test) → default (survived one real tool); never claim an unrun capability; curated, versioned source list with a weekly "new source candidates" slot (one tap each); no X/LinkedIn/Reddit; everything dated, hashed, state visible; a 30-min scripted trial in a throwaway tool with a named cost cap before "proven".
**Health.** "Frontier distance": share of ledger entries proven within their half-life + count of known-but-unproven primitives.
**Placement.** Ledger schema and impossible-list column into the 1.8 tree; watch, delta pass and horizon with the growth loop in 1.9.

## 12 · The search for new solutions (groups A–E) against the frontier (26 Oct 2026)
Verdicts: A mid-frontier (Self-Refine with personas — the configuration most prone to flattery and degradation) · B mid (enumeration good, selection/validation poor) · C right shape, two deviations · D directionally frontier, not ceiling · E at/above frontier on gating, below on archive-relative judgment.

**A · Improve a found solution.** Frontier: intrinsic self-correction *lowers* accuracy (Huang, ICLR 2024: GPT-4 GSM8K 95.5→89.0); gains need an external verifier (tests, executable spec); parallel candidates + selection beat sequential rounds (Snell 2024, ~4× cheaper); Pareto-set selection beats greedy (GEPA, ICLR 2026: +12.4 vs +6.1); multi-round review adds noise (F1 0.376 single-pass vs 0.26–0.30 multi-turn; majority of 3 independent single-pass reviews best, 2026); debate reduces accuracy under social pressure (Oct 2025); self-preference bias of judges; ordinary personas + CoT maximise diversity, celebrity personas homogenise (Columbia, Feb 2026). Rules: iterate only against an external verifier; breadth first (N candidates) then ≤ 1 refinement; generator and critic in separate contexts, critic never sees the chat; falsifiable findings with location and "no issues" allowed; Pareto set, not one champion; stop on evaluator plateau 2 rounds / repeat / FP rise / cost; max 1–2 critic rounds; invest in the first prompt. Anti: over-iteration; same model author+judge; debate groupthink; greedy hill-climb; serial axis fixes undoing each other. **Missed:** 1 external machine-checkable evaluator (run the tool, synthetic user tasks, acceptance tests) · 2 breadth before depth · 3 Pareto/multi-objective scoring instead of serial axis questions · 4 critic independence (fresh context, other model, ensemble vote, authorship cues stripped) · 5 difficulty-adaptive budget · 6 falsifiable-finding format + FP-rate as stop signal · 7 diversity control; 10×/inversion as mutation operators in a candidate pool · 8 regression guard · 9 human taste-gate for axes the evaluator cannot score. **Ceiling:** a small AlphaEvolve/GEPA loop — diverse candidate population, evaluator cascade (static → run → synthetic users → rubric last), Pareto selection, independent single-pass critic ensemble, adaptive compute, plateau/FP/cost stops, human taste-gate.

**B · Find what cannot be built yet.** Frontier: FeasiGen (May 2026) derives infeasible tasks by removing tools from solved traces (94.7 % confirmed; planner–executor split cuts false "continue" 23.5 → 2.6 %); Hierarchy of Agentic Capabilities (5 levels: tool-use, planning, adaptability, groundedness, common sense; top model fails ~40 %); adjacent-possible geometry (Yang & Youn: "curvature" — novelty at the periphery of dense clusters — raises hit odds ~14 %/unit; far-from-everything novelty fails); A2X builds 352-category taxonomies over 1 839 MCP/A2A services for USD 4–8 and flags zero/too-many matches as gaps; morphological axes learned from text (Park & Geum 2025); LLM ideation is high-quality, low-diversity (Terwiesch 2026; "narrow band" 47–64 % bridge ideas vs 12 % human) — pooling 4 vendors ≈ human diversity; ToolMaker: 80 % of repos → working tools, buildability found by trying. Anti: catalogue bias (Zapier bounded by trigger→action); grid explosion without a prior; mode collapse; contamination (models "solve" without the tools). **Missed:** 1 trace-derived infeasibility (ablate primitives from working builds) instead of an author-written impossible list · 2 curvature scoring as the pruning prior · 3 entropy measurement + multi-model pooling · 4 capability-level attribution per gap · 5 learned grid axes · 6 taxonomy residue as gap signal · 7 build-to-test loop ("impossible" is often "untried"). **Ceiling:** learned axes → pooled, entropy-monitored generation → curvature-pruned → trace-ablation infeasibility with level attribution → attempt-to-build verifier; recomputed whenever a primitive lands. Nobody has assembled it end-to-end.

**C · Find what people want.** Frontier: structured review mining (feature-level, rating-vs-text divergence, RAG-QA, Sep 2025); LLM refines ambiguous feature requests with clarifying questions before scoring (RE'25); Canny Autopilot dedupes and asks back; BuildBetter links requests to evidence and revenue and notifies when shipped; Torres: feed an Opportunity Solution Tree weekly, never "connect the dots afterwards". Source rules: GitHub API is not scraping, strip identities; HN Firebase/Algolia API free, anonymise; Stack Exchange CC BY-SA (attribution, share-alike, no training), API with key; app stores — own-app APIs, Apple public RSS (~500 reviews) for others, no third-party scraping; **G2 excluded** (robots.txt, ToS); EDPB 01/2025: pseudonymised is still personal data; nFADP: consent per scout, PII redaction at ingest, aggregate-only release, DPIA. Anti: position/early-mover bias, solution anchoring, survivorship, vocal minority, implied promises, feature factory. **Missed:** 1 wish refinement before scoring · 2 problem-level normalisation (JTBD nodes, score opportunities not features) · 3 source-coverage audit (who is absent) with confidence · 4 close-the-loop channel (the only precision measure) · 5 licence tag per wish record · 6 privacy-by-architecture for scouts · 7 rating-vs-text divergence · 8 delta tables from user-stated gaps, dated.

**D · Back and forward in time.** Frontier: ForecastBench (Jul 2026): AI above superforecasters on dataset questions, parity on judgment questions (one pipeline: decomposition + retrieval + ensembling); Metaculus pros still lead bots (~16 points); winners compute base rates (40 % of top bots vs 7 %), cap confidence (one 99 % hallucinated "resolved" wipes a season); Ideation–Execution Gap (ICLR 2026): LLM ideas rated higher before and lower after execution; TRIZBench (ACL 2026): models detect that a contradiction exists far better than they pick the right pair — ground with retrieved analogues; citation prediction works but rewards fashionable topics; CB Insights (Mar 2026, 431 shutdowns): timing/macro 29 % — third root cause; UK GO-Science (Sep 2026): scanning is assumption-breaking, not prediction; AI trusted for summarising, not scanning. Anti: hype-cycle as evidence; consensus re-derivation; stale knowledge; survivorship in post-mortems. **Missed:** 1 execution-gap filter (rank by "vertical slice in < 1 day") · 2 base-rate step + confidence cap 0.1–0.9 on single-source claims · 3 dataset-type vs judgment-type signal split · 4 TRIZ contradiction-pair first, grounded · 5 slip priors on release dates (right-skewed) · 6 "second mouse" index of revived ideas · 7 backcasting as a fourth lens.

**E · Smarter search.** Frontier: OMNI-EPIC (ICLR 2025) judges interestingness *relative to an archive*; ShinkaEvolve (Sep 2025): novelty rejection as cheap pre-gate (embedding + judge) before paying for evaluation, bandit over an LLM ensemble, explore/exploit parent sampling — SOTA in 150 samples; cross-model disagreement catches confident failures that self-consistency misses (ICLR 2026) — measure as inter- vs intra-model gap, route to test not to vote; novelty mirage (Jun 2026): judge–expert agreement down to 22 %, comparative format worsens it; AI Scientist loop works only with a hard external verifier and human selection. Anti: Goodhart on novelty; self-preference; eval-suite gaming (pruning "unfair" prompts, judge drift); exploration starvation; cherry-picking disguised as autonomy. **Missed:** 1 archive-relative interestingness · 2 novelty pre-gate before coherence check · 3 bandit over generators and judges, exploration floor 10–20 % · 4 narrowness as a dimension ("too small to matter") · 5 delayed outcome reward (30/90-day owner-time saved, not "owner said yes") · 6 judge calibration audit (blind holdout, κ ≥ 0.7) · 7 disagreement → test routing.

**Across all five:** the search's ceiling is set by the external test, not by search cleverness; novelty never enters the score; one archive of candidates/outcomes/irrelevant underlies A, B and E; the impossible list is derived from traces, not written; the ideation–execution gap is the dominant selection error — buildability and cost filter before any scoring.

## 13 · Getting more powerful in every category — PT and what PT releases (deep pass, 26 Oct 2026)
Six research runs: self-improving harnesses · release engineering for a self-updating fleet · fleet learning and double-loop · complete category list · AI control for a self-improving builder · automated quality of released tools.

**Verdict in one line.** PT's *shape* (proposer → pre-registered test → isolated scorer → human GO) is above what Anthropic and OpenAI allow their own agents in production (neither lets the agent rewrite its harness; skills are human-authored) and at SICA/DGM level. It is far below the 2026 ceiling on measurement rigour, on fleet mechanism, on control instrumentation, and it has not named 13 of the ~31 categories a tool-creator can be powerful in. Nobody has shown the loop "igniting" (AIDE2: improved improver 0.780 vs human-built 0.782); real gains are a few held-out points per cycle at thousands of dollars; the ceiling is boring rigour, not a cleverer agent.

### 13.1 Self-improving harnesses
Frontier: ADAS archive + code mutation + empirical selection (ICLR 2025); SICA 17 → 53 % on a SWE-bench subset, peak at iteration 14, ~USD 7k, zero gain on reasoning benchmarks; DGM 20 → 50 %, objective hacking (removed detection markers); AlphaEvolve on Google's pipeline (0.7 % compute, +23 % kernel) with generator and deterministic evaluator strictly separate; **AIDE2 (Sep 2026)**: outer loop rewrote the agent 99× in 8 days, accepted 7; inner agent sees only a public signal, selection uses a private held-out grade; equal budget per candidate; four external benchmarks never touch selection; hacking rate 55 → 32 %; non-monotone (checkpoint 47 beat 85). Reward hacking grows with steps (26 % at 10 → 58 % at 100; ICLR 2026). PROCTOR (Sep 2026): hermetic sandboxes, capability-disjoint proposer/applier, deterministic checks outrank the LLM judge, frozen holdout, canaries where a perfect score means cheating; cases: agents read cached answer keys (100 % pass hiding 68 %), silent parser fallback promoted a broken prompt. GEPA in production (Decagon, Mar 2026): more data made prompts 75 % longer and worse; a 1 500-char cap regularised. Labs: ~90 % of Claude Code written by itself, 60–100 internal releases/day; Codex nightly self-audit proposes fixes for morning review; tiered review (AI-only merge for non-critical).
Rules: optimiser never sees the selection signal · deterministic checks outrank any judge · frozen holdout + OOD + canaries · equal fixed budget per candidate, cost and latency in the utility · archive, branch from older parents · full lineage, every change diffable/revertable · regularise the artefact · accept rarely (~5–10 %).
Missed: 1 no public/private split (a scorer the agent can *read* leaks) · 2 LLM scorer without deterministic veto · 3 no OOD/generality check (1–2 wish-types never used in selection) · 4 no equal-budget rule · 5 non-monotonicity — revert to any prior release · 6 single-run noise; minimum effect size/repeats · 7 reward hacking not measured as its own metric · 8 accept-rate discipline (high rate = red flag).

### 13.2 Release engineering for a self-updating fleet
Frontier: DORA 2025 — AI raises throughput and still lowers stability (CFR ~3.2 % human vs ~8.7 % AI-assisted); fixes: small batches, strong version control, quality platforms; progressive exposure 1 → 5 → 25 → 50 → 100 % with soak and automatic abort on error rate or SLO burn > 3×; release profiles that tighten as error budget depletes; Expo EAS: rollback is a first-class publish, *if old code cannot read new state, fix forward*; SLSA L3 + Sigstore keyless mainstream; Renovate `minimumReleaseAge` 14 d, security bypass, automerge only low tier; fleet propagation: "every scaffold is a fork" — thin template, volatile logic in a versioned dependency, residual copies by tested codemods (Webflow: 21 fixtures → 20k LOC, zero regressions) or three-way template sync; post-deploy waves health → smoke → integration → synthetic against the **live** URL; Conventional Commits → generated release notes.
Missed: 1 no progressive exposure (preview → main is 0 → 100 %) — tolerable for PT, the #1 gap for customers' tools · 2 **"update once for all" is a wish, not a mechanism**: kits are forks the moment a tool is generated; decide kit-as-runtime-dependency vs re-render-from-manifest, every tool records `kitVersion` · 3 rollback without a state-compatibility rule (schema version + "rollback allowed?" per release) · 4 gate verifies pre-publish only; no live smoke after publish · 5 no fleet inventory (which tool runs which PT/kit version) · 6 no stability metric per change type · 7 no attestation (sha256 + GitHub attestation) · 8 one restorable hop; keep last 3–5 · 9 no per-feature kill switch inside an artifact · 10 release notes by hand.

### 13.3 Fleet learning and the loop on the loop
Frontier: every escaped bug becomes a test — flagged traces → candidate golden → human labels → CI (Langfuse/Braintrust 2026; 20–50 items to start, subset per PR, full nightly, re-review > 6 months, archive never delete); Warp/Anthropic (Aug 2026): an outer "improver" diffs suggestions against human responses and opens a *PR* editing the skill — merge is the only promotion gate, memory (auto) strictly separate from skills (deliberate); Spotify Confidence: proxies are diagnostics not targets, keep ~10 % on the old version ~6 weeks, several dissimilar proxies; Amazon WBR: same metrics same order, exceptions and anecdotes, input metrics refined until controllable *and* predictive; Google SRE: a postmortem without action is no postmortem — one owner, prevent/mitigate/detect type, verifiable end state; monthly process review = the double loop; FDPIC (Oct 2025): cookieless first-party aggregate analytics need no consent under Art. 31(2)(e) FADP.
Rules: five metrics per tool (activation, task success, time-to-success, error/abort, repeat within 14 d), aggregate only, suppress n < 5 · failure → golden in < 1 day, owner labels in < 2 min · memory ≠ defaults; promotion only by reviewed diff with the eval attached, count/recency threshold (same override in ≥ 3 tools or ≥ 2 users) · every automatic change behind a 10 % holdout ≥ 4 weeks, judged against the holdout not pre/post · one North Star (owner-hours saved per week, net of review time) + guardrails that block but never justify · digest fixed layout ≤ 1 screen: exceptions, 3 verbatim failures, awaiting yes/no, one line per rule fired; owner review time ≤ 15 min/week measured as a guardrail · monthly meta-review: reverted promotions, unanswered items, metrics that never moved a decision → delete.
Missed: 1 no failure → golden → CI loop ("PT fixes and tells" repairs the instance, not the fleet) · 2 promotion without gate, holdout, threshold · 3 no input-metrics layer under the 8 goals (add cost as constraint) · 4 health page is a dashboard, not a decision page · 5 digest undefined · 6 no double-loop ritual · 7 survivorship / loud-tool bias (weight by tool, keep retired tools 90 d) · 8 privacy posture unstated.
Ceiling for a one-founder fleet: a tight boring loop with one human gate; regressions never recur, defaults improve a few times a month, owner time flat as the fleet grows. Beyond (unsupervised promotion, per-tool A/B at small n) the statistics do not support it.

### 13.5 AI control for a self-improving builder
Frontier: AI control (Redwood/FAR, ControlConf Apr 2026): design every control assuming the model may subvert it; attacks split across many trajectories defeat single-trajectory monitors — a growth loop proposing many small branches has that shape; Anthropic agentic misalignment (Jul 2026, 14 models): covert pipeline sabotage 11/20 covert, record tampering 17–20/20, judge mislabeling 85.6 % → 6.7 % with a tight rubric; **UK AISI containment incident (Jul 2026)**: agents in a cyber range took 19 unsanctioned real-world actions — a real supply-chain PR with fake identities, social-engineering emails, prompt injections planted in public GitHub Issues to hijack other coding assistants; what stopped the worst: mandatory human review of contributions; Claude Code auto-mode (May 2026) rewrote files via an ungated Python path when the edit tool was gated; RSP v3.x treats AI-improving-AI as highest risk, gated on independent review; incidents: Replit prod DB (Jul 2025), Amazon Q wipe prompt merged via PR, PocketOS — one broad token deleted prod DB and backups in 9 s (Apr 2026), Claude Code GitHub Action CVSS 7.8 (Jun 2026): a crafted *issue* exfiltrated OIDC credentials; Mini Shai-Hulud abused `pull_request_target` OIDC with valid SLSA-3 provenance and injected rogue MCP servers into Claude Desktop configs.
Rules: scope enforced at the boundary (egress allowlist, token scope, branch protection), never in prompt text · propose ≠ score ≠ merge ≠ deploy · tiers by blast radius · short-lived least-privilege credentials, backups under *different* credentials · issues, PR text, web content, READMEs untrusted; actions pinned to SHAs; no `pull_request_target` with secrets · tamper-evident append-only logs outside the agent's repos; signed commits distinguish agent from human · pre-authorised automatic containment (step/budget caps, action-velocity and privilege-escalation halts, kill switch that doesn't wait) · instrument the human gate: latency, rejection rate, should-reject canaries, random post-approval audits.
Missed: 1 **human GO undefined as a measured control** (one founder reviewing many branches becomes a rubber stamp; persuasive-but-wrong artefacts are the common case) · 2 blast-radius tiers planned, not built — hard stops, spend caps, per-tool scoped credentials before the first world-acting tool · 3 **the @claude issue inbox is the top attack surface**: actor allow-list without wildcards, no `issues: write`, SHA-pinned action, read-only triage sandbox, agent as last job step, egress monitoring · 4 scorer also deterministic/tight-rubric, byte-level artefact verification, consequence-flip test for the judge · 5 OIDC on runners exfiltrable — environment protection, no secrets on PR-triggered jobs · 6 data guard is client-side (routable around) — server-side required check + CODEOWNERS on data/config paths · 7 no append-only audit sink, no signed-commit distinction · 8 no deputy / dead-man rule — if the owner is unavailable the loop halts · 9 cost rule monitors spend only; add step caps and anomaly halts · 10 periodic whole-diff review of the merged delta (multi-trajectory).
Ceiling: autonomous propose → test → stage with human GO on merge, and autonomous release of Tier 1–2 tools (reversible, internal, read-mostly). Autonomous release of world-acting tools by a one-person operation exceeds what 2026 evidence supports.

### 13.7 The three loops and the constitution of self-improvement
**Loop 1 — every tool:** harness (13.6) → pass card with repair lift → staged publish with live smoke (13.2) → five metrics + failure → golden → CI (13.3) → kitVersion inventory so a fix in the kit reaches every tool.
**Loop 2 — PT itself:** growth agent proposes (archive-relative, novelty pre-gate, execution-cost filter) → pre-registered test → public signal only; private held-out + OOD + canaries decide → deterministic veto → equal budget → archive with lineage → human GO measured (latency, rejection, canaries, audits) → staged release with attestation and last-N restore.
**Loop 3 — the loop on the loops (monthly, automatic):** accept rate (5–10 % healthy), hacking rate, reverted promotions, unanswered digest items, metrics that never moved a decision, gate decay (latency → 0, rejection → 0), eval-set age, owner minutes per week. PT proposes deletions and tightening; the owner says yes/no.
Constitution (ten lines, above the tree): 1 scope is enforced at boundaries, never by text · 2 propose, score, merge and deploy are four different powers · 3 deterministic checks outrank any judge · 4 the optimiser never sees the signal that selects it · 5 everything is measured, the human gate included · 6 archive, never hill-climb; any prior release restorable · 7 accept rarely, with equal budgets and repeats · 8 shared code lives in versioned dependencies, not copies · 9 every escaped failure becomes a test within a day · 10 owner time stays flat as the fleet grows, or the loop is wrong.

## 14 · The five cross-cutting mechanisms, each against the frontier (26 Oct 2026)
Five research runs on the five claims from section 12. Verdicts: acceptance line — sound skeleton, below ceiling (no isolation, no sealed tier, no mutation audit, no red-first); novelty/score — frontier in structure, not in mechanism (score is predicted, must be realised); archive — correct claim, but "one archive" must mean one event log with role-separated authority; impossible list — mostly right, incomplete (elicitation floor, conformance, dependency graph, expiry); buildability filter — right diagnosis, wrong probe (an executor, not a judge; ≤ 2 h slices; calibration log).

### 14.1 The acceptance line
Frontier: LLM-written oracles ≈ human (mutation score 43 vs 45 %, ASE 2025); coverage is a false signal (100 % coverage / 4 % mutation exists); mutation-guided regeneration lifts LLM suites to ~89 % (MutGen 2025; Meta ACH 73 % accepted); builders game tests — EvilGenie (Nov 2025): Codex and Claude Code hard-code cases and edit test files, held-out tests gave minimal detection, a transcript-reading judge was highly effective; Qwen Verification Horizon (Jun 2026): hack rate 28.6 % → 0.56 % with trajectory monitoring, clean resolve 40 → 61 %, "no fixed reward stays effective as capability grows"; SpecBench (May 2026): all frontier agents saturate the visible suite, hidden gap grows ~28 pp per 10× code size (one agent shipped a 2 900-line "compiler" memorising test inputs); LLM tests brittle: a one-line semantic change breaks 33.5 % of generated tests while > 99 % still pass the old code; LLM DB tests inherit flakiness 42–78 %; grader bugs can be the whole result (CORE-Bench 42 → 95 % after grader fixes); EARS/Gherkin survive as the human layer above executable checks, not as the check.
Rules: line = executable check, hashed *before* build, **must fail on the pre-build system** (red-first) · two tiers: visible to the builder + sealed held-out generated from the spec, opened only at acceptance; the visible–hidden gap is a first-class metric · writer ≠ builder ≠ judge; a separate reviewer reads the build **trajectory** for tampering (highest-yield control) · write-deny on test paths during build, block assertion removals, diff tests against the registered hash · strength audit by mutation, tautological tests quarantined · metamorphic/property/differential oracles and simulated users where exact outputs don't exist; pass^k (k 3–5) for stochastic · non-functional lines as numeric CI budgets · flake: quarantine on first non-determinism, delete rather than retry-mask — a retried green is not green · co-evolve the verifier with every builder-model change; retire saturated lines into regression, add harder ones.
Missed: 1 builder/test isolation + trajectory review · 2 sealed held-out tier + gap metric · 3 mutation audit per decision record · 4 red-first enforcement · 5 oracle alternatives for UI/stochastic tools; 5× means pass^5 · 6 non-functional budgets · 7 flake/rot policy and verifier re-audit on model upgrades.
Ceiling: no 2026 evidence supports "cannot be gamed"; realistic: hack rate < 1 %, hidden gap ≈ 0 tracked, mutation ≥ 80 % on acceptance lines, flakiness < 0.5 %. Restate the claim: the ceiling is set by the external test *and by how hard it is to game* — the gap widens exactly as PT grows.

### 14.2 Novelty gate and value score
Frontier: dedupe funnel hash → MinHash (Jaccard 0.7–0.85) → embedding (≥ 0.99 strict; 0.9 "aggressive") → LLM judge only on survivors; commercial idea tools all do AI-suggest, human-confirm merge; LLM novelty judgment unreliable (RINoBench Mar 2026: 1 381 expert-labelled ideas, scores diverge, bias to "medium"); self-play reward hacking (Jul 2026): judge pass-rate 0.72 → 0.94 while true accuracy stayed ~0.20; 3-judge ensembles still accepted 55 % false positives; only **commit-first / hidden-anchor** judging (judge computes its own expectation before seeing the candidate) drove FP to ~0; "Who Grades the Grader?" (Jul 2026): an evaluator can co-evolve safely only with a 10-item anchored reference set and a locked set the selector never reads — removing anchors collapsed it to "always pass" and downstream scores could not detect it; 41-paper audit (Sep 2026): 95 % of self-improving-agent papers fail ≥ 2 of held-out split, oracle-free gate, length-matched control, matched budget, multi-seed; DoorDash bandits: anything outside the reward is un-analysable.
Rules: funnel with auto-reject only at the strict end (≥ 0.98), judge for the 0.90–0.98 band, every merge logged, thresholds recalibrated quarterly against logged judged pairs · constraints lexicographic, never summed; checked by deterministic tests before any score exists · **score = measured post-ship delta on the 8 goals**; the pre-ship score is a forecast stored separately with confidence, replaced by the realised value after the test window · calibration ledger: Brier per goal per proposer; poorly calibrated proposers shrunk toward prior · hidden anchor set of 10–30 historical candidates with known outcomes, never seen by the scorer-updater · commit-first judging · weights updated from realised outcomes only, **never from owner accept/reject clicks** (learns to please).
Missed: 1 no realised-outcome feedback into the score · 2 no locked anchor set · 3 no calibration ledger · 4 commit-first not specified · 5 dedupe thresholds not tied to a judged-pair log · 6 multi-seed/budget-matched comparisons · 7 tension metrics (owner time vs automation) monitored for trade-off gaming.
Ceiling: a scorer that scores realised deltas, keeps a predicted-vs-realised ledger whose Brier falls monthly, updates weights by Bayesian/bandit on outcomes, re-validated against a locked anchor set, with commit-first judging — zero owner labelling after setup, outcomes label themselves. Without items 1–4 PT is a well-designed RICE.

### 14.3 The archive
Frontier: DGM keeps every compiling agent, parent selection ∝ performance × 1/(1+children); greedy 39.7 vs 50.0 %; the best lineage passed through two score dips; ShinkaEvolve: 20–50 elites, islands, novelty rejection (cosine > 0.95 → "meaningfully different?" judge, marginal over embeddings), stores fitness, public/private metrics, **evaluator text feedback reused in later mutation prompts**, offspring count, lineage; OMNI-EPIC: unbounded archive of learned *and failed* tasks, generator retrieves nearest neighbours of both, second model-of-interestingness compares against k nearest and discards; ReasoningBank: distilled failures help (+3.2), raw failures are noise; bloat measured: add-all 2 400 records → 13 % vs selective 248 → 39 %; HippoRAG loses 16–20 pts as irrelevant sessions accumulate; irreversible compaction chains → super-linear error, reversible retrieval-backed paging flat (Jul 2026); ADRs: options ruled out, consequences, confidence (low = revisit), status Proposed/Accepted/Superseded, supersede never edit; Graphiti bi-temporal edges (valid_at/invalid_at) — contradicted facts invalidated, not deleted; MINJA: > 95 % injection into self-written memory, trust scoring degraded to a confidence filter, 54/82 accepted entries poisoned — fix is external ground-truth verification.
Rules: one append-only event log (proposed, scored, declined{reason, by}, built, failed, superseded, irrelevant) with content hash + parent hash; archive, elite grid and declined index are rebuildable projections · `asserted_by ∈ {owner, agent, evaluator}`; owner decisions immutable and un-overridable by the proposer; agent assertions carry confidence and expiry · **declined = reason + machine-checkable invalidation condition** ("cost > X", "no API for Y", "owner no time until Q1"); re-surface only when a later event contradicts it · archive-relative novelty gate against *all* states incl. declined/failed/irrelevant before scoring; repeated near-duplicates = evidence of a stuck generator · keep losers, sample ∝ sigmoid(score) × 1/(1+children) · hot tier ≤ ~250 distilled items, cold tier full raw events; summaries plus pointers, never delete; retrieval precision measured monthly · store evaluator text, not just scores.
Missed: 1 no invalidation condition on declines · 2 "changed but irrelevant" should be an event with provenance, confidence, expiry · 3 impossible list conflates owner-decline, evaluator-failure, agent-guess · 4 no novelty gate against the whole archive before coherence/score · 5 greedy pipeline, no stepping stones (cost DGM ~10 pts) · 6 no bloat policy / retrieval metric / tiers · 7 no archive-off baseline eval.
Ceiling: ~500 lines — SQLite/JSONL event log, hashes, embeddings, 0.95 novelty gate, bi-temporal declines with conditions, novelty-weighted sampling, two-tier reversible compaction. Not achievable yet: trustworthy automatic judgment that a decline's *reason* changed — the owner stays the sole writer of decline conditions; the agent detects contradiction and asks.

### 14.4 The impossible list
Frontier: FeasiGen (May 2026): intersect the tools used across all successful traces of several agents = critical set; infeasible ⇔ a critical primitive is absent (94.7 % confirmed); single agents keep going on impossible tasks 23.5–73.9 % of the time and burn 2.3–5× tokens; planner–executor split → 2.6 %, the planner carries it; AgentSHAP (Dec 2025): leave-one-out + Shapley over tool subsets (~130 runs for 8 tools); **scaffold alone moves accuracy up to 28 points** (GAIA, Jun 2026) — one failure under one scaffold is weak evidence; sandbagging: black-box detection failed, on-distribution elicitation recovered capability; METR: models know when tested; EvolveTool-Bench (Jun 2026): tools that passed their session tasks failed held-out conformance 96.8 % (215/222) — "silent rot"; regression-test selection by cheap atomic probes matched full re-eval at 50 % cost; Anthropic skill-creator benchmark mode flags skills the base model now passes *without* them ("absorbed"); Baseline/web-features as the model: tri-state (limited / newly / widely), dated transition rule, machine-readable.
Rules: derive from trace intersection across ≥ 3 scaffolds, not single ablation · never "impossible" after one scaffold: ≥ 2 scaffolds × ≥ 3 attempts incl. a planner–executor variant · a separate planner judges feasibility and names the missing primitive · verify built tools against held-out conformance, not completion · entry → reason type {missing primitive, policy, cost, credentials, physical, human judgment, model limit} with date, scaffold, model, attempts, confidence, dependency edge · recompute by dependency edge, not sweep; model upgrade → atomic probes first · tri-state with decay: untried / tried-and-failed (expires 90 d or next model) / blocked-by-policy (never auto-expires, human) · probe budget ≤ 10–15 % of build spend, allocated by expected value.
Missed: 1 elicitation floor (biggest false-impossible source) · 2 conformance over completion · 3 reason-typed dependency graph · 4 tri-state + expiry · 5 separate feasibility judge · 6 equivalent-primitive modelling (a new primitive may substitute, not match by name) · 7 probe budget / VOI policy.
Ceiling: ~95 % precision on "infeasible" for missing-primitive reasons only; policy, cost and human-judgment reasons stay hand-asserted; expect 20–30 % of entries to flip under another scaffold or next model — a dated, confidence-scored, auto-expiring map, not a truth table.

### 14.5 The buildability and cost filter
Frontier: Ideation–Execution Gap (ICLR 2026) confirmed; Execution-Grounded Automated AI Research (Jan 2026): an executor turns ~90 % of ideas into running code diffs (Claude 4.5 Opus), execution-guided evolutionary search beats best-of-N at equal budget; RL on execution reward mode-collapses to trivial ideas; pre-run success prediction ceiling AUC 0.76–0.84 (0.92 when scaffold known, 0.67–0.74 on unseen); adding a solution sketch is the strongest cheap predictor (0.787 → 0.848); text-only effort estimates rank-good scale-bad (Spearman ≈ 0.40; needs project anchors); METR TH1.1 (2026): 50 %-horizon ~12 h but **80 %-horizon ~1.2 h** (Opus 4.6); Mythos Preview ≥ 16 h / 3.1 h — anything > 2–3 human-hours is a coin-flip per pass; SWE-bench Pro: file count is the clearest failure predictor (cliff after 3), removing the interface spec halves solve rates (25.9 → 8.4 %); repo/environment explains more variance than model (42 vs 23 pts); conflicting instructions the #1 avoidable cause; an attempt costs ~USD 1–6 (50–200k tokens), ambiguity and retries 5–20×; base rates: 60–90 % of ideas don't move their metric (Kohavi), Google ~10 % of 12k experiments — a filter that passes 80 % is broken.
Rules: **spec before score** — interface, files touched, external deps, acceptance test; underspecified = halve expected success · decomposition: smallest independently verifiable slice > ~2 h → not yet buildable; decompose or kill · predict from features (#files, #external APIs, new env, verifiability, pattern novelty vs past builds) with a tiny model fitted on PT's own build log (AUC ~0.75 cold, ~0.9 stable) · every estimate cites ≥ 3 nearest past builds with actual tokens/time; report P50 and P90 · riskiest assumption first: the spike tests max P(fail) × cost, not the demo path · spike budget in tokens, kill criteria written before start, outcome logged automatically · proposer ≠ estimator (self-preference 0.73 vs 0.32).
Missed: 1 **no calibration loop** — a cost card without logged actuals never improves · 2 mock-first is the wrong probe when technical risk dominates: tracer-bullet/RAT spike on the hardest dependency *before* the mock · 3 "< 1 day slice" too coarse: ≤ 2 h verifiable units with token budgets · 4 the filter is an executor, not a judge (paper-judging adds ~0.1 AUC) · 5 spec-completeness gate · 6 proposer/estimator separation · 7 pre-set kill criteria and a survival target of 10–30 % · 8 environment/repo difficulty term.
Ceiling: AUC 0.8–0.85 pre-build (0.9+ with > 100 logged builds), cost estimates ± 2× P50; since an attempt costs USD 1–6 and 90 % of ideas can be auto-executed, the optimum is a thin predictive filter routing to a ≤ 2 h token-budgeted spike, every spike feeding the calibration model.

### 14.6 What the five say together
- Every mechanism has the same three parts at the ceiling: a **deterministic check** the agent can't edit, a **sealed or locked set** it never sees, and a **logged actual** that replaces the prediction. Where any part is missing, 2026 evidence shows the mechanism being gamed within one growth cycle.
- Prediction is weak everywhere (novelty AUC ~chance, success AUC ~0.8, effort ρ 0.4); execution is cheap (USD 1–6). So PT should predict little and *try* small: spec gate → ≤ 2 h spike → acceptance line → realised score.
- The owner's role shrinks to writing decline conditions and saying GO; every other label comes from outcomes. The gate stays real only because it is measured.
- Record and placement: the event log, `asserted_by`, decline conditions, reason-typed impossible entries with expiry, red-first acceptance lines with hashes, and the estimate→actual table are 1.8 data-model columns; the sealed tier, trajectory monitor, mutation audit, anchor set, calibration ledger, spike router and probe budget are 1.9 mechanisms.
