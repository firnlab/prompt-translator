# TREE-1.8 — the decision tree of everything PT can build (researched 25 Oct 2026)

Every tool PT makes is the sum of its decisions. This tree lists every direction a wish can go, the decisions under each,
PT's recommended default, and a fact card per direction. CHECKED = read on a first-party page on 25 Oct 2026 (source at the end
of each branch); SECONDARY = third-party page; ESTIMATE = computed or rule of thumb; LAW = statute. CHF from USD at ~0.80–0.90 (ESTIMATE).
Facts older than their re-check interval (AI prices 90 d · plan prices 90 d · payment fees 180 d · VAT 12 months · statutes on amendment)
are flagged STALE by PT (rule 5 of the honesty set).

## 0 · The shape of the tree

- **L0 Wish** — the owner's words; PT's reading(s); the result the owner will hold.
- **L1 Direction** — one of 13 (A–M), or a pair ("B+C"); "M manual / do without" is always shown as the honest baseline.
- **L2 Shape** — where it runs · what stores data · which parts are AI / code / a person · what is read (untrusted) and what acts outward.
- **L3 Money & platform** — hosting · login · payments · models and credits · media cap · legal pages · privacy notice.
- **L4 Build & run** — who builds (chat / cloud job / GitHub issue / laptop) · tests (3× or 5× if it acts outward) · updates · done.
- Every node: status = decided by you · assumed by PT (marked) · open. "Live" needs no open node at L1–L3 and nothing hard assumed.
- Fact card on every option: one-off CHF · monthly CHF · credits per run · time to first version · time to finished · your hours ·
  automation % · reliability · safety · data & privacy · legal line · lock-in / exit · dependencies · maintenance h/month ·
  paid-tool potential · what you give up vs the siblings · confidence + date on every number.

## 1 · The thirteen directions (L1) — one line each

| | Direction | Right when | Wrong when |
|---|---|---|---|
| A | Chat-only: prompt · Claude Project · Skill | text/analysis output, a person in the chat each time, no shared state | several people must see one record; numbers over time; must run alone |
| B | A page (artifact: tracker, board, calculator, poll) | shared record, buttons, data accumulates, others use it without prompting | multiple routes, server auth, secrets, anonymous public users, SLA |
| C | A scheduled tool (radar, scout, report, watchdog) | predictable input, output is a report/draft, a missed run is harmless | it must act on the world (→ D); the trigger is an event, not a clock |
| D | An agent that acts (reads untrusted content and sends/posts/orders) | volume or speed justify it, actions reversible or gated, you can monitor | a draft-only tool would do; financial/legal acts without a human signature |
| E | A web app with users and money | accounts, shared data, public URL, recurring revenue | a page or script does it; no hours/month for accounts, backups, legal pages |
| F | A phone app | home-screen presence, push on iOS, camera/BLE/Health, store credibility | a PWA covers it (stores add fees, review, 15–30 % commission) |
| G | A media/document producer (images, voice, dictation, video, slides) | a human judges the output by eye/ear; a hosted or open model does 90 % | the real need is the text/data inside; a voice/face that isn't yours |
| H | A company of tools (roles, shared records, founder gate) | work is genuinely parallel, runs daily unattended, worth 3–15× the tokens | one agent would do; roles are just sequential phases; no verifiable "done" |
| I | An existing product does it (pay · clean-room · interop RE · without) | the wish is generic and the product costs < ~5 h of your time per year | it locks your data; fails a core requirement; the wish is to own the tool |
| J | Laptop, local models, devices (clicks, zero-credit AI, Shortcuts, Pi) | needs your logged-in apps/devices, offline or private data, free bulk inference | must run 24/7 unattended; needs top-tier reasoning; targets locked hardware |
| K | A data/analysis tool (sheet, chart page, dashboard, pipeline) | data exists somewhere; the question is "what is happening"; few editors | many users entering records with rules (→ E); the "data" is a document |
| L | An integration/connector (MCP server, automation, webhooks, GitHub glue) | two systems must stay in sync; an action on an event | a monthly copy-paste is fine; no API; irreversible high-stakes without a gate |
| M | Manual / do without | the honest baseline: what the wish costs in CHF/year and hours/year by hand | — |

Pairs PT allows as one path: B+C (page + scheduled feeder), E+F (web app + phone shell), C+K (pipeline + dashboard), H+any, I-pay+any.

## 2 · Branch cards (L2–L4 decisions · defaults · fact card · limits · sources)

### A · Chat-only (prompt · Project · Skill)

- Best practice: smallest shape; short Project instructions (Anthropic's own advice); remove stale files; Skill description as a trigger sentence; SKILL.md short, details in files; test with 5+ prompts; never a key in a skill; one example of good output; version SKILL.md in git; review third-party skills (injection risk). ### C · A scheduled tool

### D · An agent that acts
- Decisions: engine (Managed Agents with built-in confirmation events, webhooks, budgets | Agent SDK on your infra | routines only for draft-only actors) · gates per tool (`always_ask` on every outbound tool; `auto` is not a human checkpoint) · trigger (event over schedule) · approval channel (one you actually check) · budget per session (USD 1–5) · memory with a review step · watchdog (webhooks on pause/fail, budget alert, daily canary run).
- Best practice: break the lethal trifecta (private data + untrusted content + outbound channel never in one unguarded session); separate accounts/tokens for the agent; domain allowlists; label untrusted input as data; hard dollar cap; canaries in test inputs; propose → approve → execute; secrets via Vaults; no self-written instruction memory without review. ## 4 · Deciding with the fewest clicks (the UI contract for 1.8)

1. **PT pre-decides the whole path from the wish** (rules + research give every node a ★); the tree opens filled. Looking, not filling.
2. **One tap per node; swipe or long-press opens the siblings as a comparison table** (fact rows × options). Keys: Enter = ★, 1–9, L = later.
3. **"Take all ★ on this level"** (direction · shape · money · build); hard nodes excluded — each needs its own tap.
4. **Decide by example**: "like my Watch tool, but weekly" → copies that tool's path, asks only the differences.
5. **Decide by sentence**: "private, free, weekly, no login" → mapped onto nodes, shown, Undo.
6. **Only differences are asked**; order = pruning power (audience, money, where it runs, then details); every card says which branches it decides between; a decided node is never re-asked — a changed fact behind it flags it.
Targets: simple tool = one sentence + 3–5 taps to a first version; complex system = one sentence + ~10 taps, the rest ★-confirmed by level.
